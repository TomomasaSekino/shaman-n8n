## 0.1 AIOSEO の項目設定

**認証と権限**
- 記事キュー「サイト共通設定」の kuroaji 行の認証情報で、administrator としてログインできる。
- AIOSEO の編集権限 `aioseo_page_general_settings` などを持つ。

**現状**
- 下書きと公開記事の全70件で、AIOSEO の `title`、`description`、`keyphrases` はすべて空だった。

**書き込み検証**
- `POST /wp-json/wp/v2/posts` の本文に `aioseo_meta_data` を含めると、作成と同時に保存された。
- 保存を確認した形式は次のとおり。`keyphrases` はオブジェクトのまま送ってよい。

```json
{
  "aioseo_meta_data": {
    "title": "SEO タイトル",
    "description": "メタディスクリプション",
    "keyphrases": { "focus": { "keyphrase": "アジング秋アジ攻略" }, "additional": [] }
  }
}
```

**TruSEO の結果の読み出し**
- 編集画面で解析された結果は `GET /wp-json/aioseo/v1/post?postId={id}` の `data.currentPost.truseo` に項目別の点数で保存される。9 が合格、6 が要改善、3 以下が不合格。
- 総合点は `seo_score`、フォーカスキーワードの点は `keyphrases.focus.score` に入る。
- 実機テストの後に、この API で項目別の結果を機械的に確認できる。

**結論**
- 2.1 は別の API 呼び出しを増やさず、Build WP Post の本文に `aioseo_meta_data` を加えれば実装できる。
- テーマ用の `st_description` への書き込みは維持する。

## 0.2 P1 に出典が無い原因

**原因**
- P1 のリクエストでは、モデルが Google 検索ツールを使わずに回答している。実行 1294 の P1 リクエストをそのまま再送しても、検索クエリも出典も返らなかった。
- ツールは「使ってもよい」扱いで、使うかどうかはモデルが決める。
- ツール指定の書き方は原因ではない。`googleSearch` と `google_search` のどちらでも、短い調査依頼なら出典が返った。
- P1 のプロンプトに「回答前に必ず Google 検索を実行する」と1行足しても、検索は走らなかった。

**代替案の検証**
出典探しだけを頼む短いリクエストを、実際のキーワードで3回送った。

| 回 | 検索 | 出典数 | 実在ページに解決 | 所要時間 |
|---|---|---:|---:|---:|
| 1 | あり | 8 | 7 | 50秒 |
| 2 | あり | 8 | 8 | 49秒 |
| 3 | あり | 8 | 7 | 43秒 |

- 出典 URL は `vertexaisearch.cloud.google.com` のリダイレクト URL で、302 で元のページに解決できる。
- 解決できなかった2件は、接続エラー1件とボット拒否とみられる 403 が1件。
- 出典は釣り専門メディアが中心で、公的機関は少ない。

**結論**
- 3.4 は P1 を変えず、出典探索用のリクエストを別に追加する。
- リダイレクトを解決し、HTTP 200 を確認できた URL だけを候補にする。
- 1記事あたりの所要時間が約45秒増える。

## 0.3 内部リンク候補の作り方

**WordPress 検索 API の挙動**
- 空白の無い正規形、例えば `アジング秋アジ攻略` で検索すると0件になる。
- 空白で区切ると AND 検索になり件数は出るが、並び順が関連度になっていない。
- タグは「ピックアップ」1個だけ、カテゴリは【研究データ】に55記事が集中しており、絞り込みには使えない。

**全記事取得と手元での採点**
- 公開記事69件を本文込みで取得すると 4.7MB、1.8秒だった。タイトルと抜粋だけでは見出しが取れない。
- 採点は、語ごとに「タイトル出現×6＋見出し出現×3＋本文出現（上限10）」を数え、全記事での出現の少なさで重み付けした。どの記事にも出る「アジング」はほぼ効かなくなる。

| キーワード | 上位の候補 | 評価 |
|---|---|---|
| アジング リーダー 長さ | リーダーの長さと最適な選び方、PE とリーダーの結び方 | 適切 |
| アジング 釣れない 原因 | 釣れない時期を克服、昼間に釣れない理由、プラグで釣れない原因 | 適切 |
| アジング 常夜灯 攻略 | 常夜灯なしでも釣れる闇夜の攻略法 | 1位は適切、2位以降は「攻略」に引っ張られる |
| アジング ジグヘッド 重さ | ジグ単の基本、入門講座、リグの種類 | 関連はあるが、重さを主題とする記事は無い |
| アジング 秋アジ 攻略 | 「攻略」を含む汎用記事 | サイト内に該当記事が無く、候補にすべきでない |

**結論**
- 3.1 は、全記事を取得し、KEYWORD と P2 の h3 見出しに含まれる語で希少語重み付けの採点をして上位5件を候補にする。
- 最低スコアの足切りを設け、該当記事が無ければ候補ゼロを許容する。足切り値は 3.6 のオフライン検証で決める。

## 0.4 フォーカスキーワードの正規形と配置

**正規形**
- キューの KEYWORD を NFKC 正規化し、全角・半角の空白を除いた文字列とする。例: `アジング　秋アジ　攻略` → `アジング秋アジ攻略`
- AIOSEO はフォーカスキーワードを入力どおりの完全一致で判定する。空白入りの形は、日本語の本文にそのまま現れないので使わない。

## 0.5 日本語 slug

- REST で `slug` に正規形を送ると、WordPress は `%e3%82%a2…` とエンコードして保存し、デコードすると正規形に一致した。
- WordPress の slug は200文字が上限で、日本語は1文字がエンコード後9文字になる。正規形が22文字を超える場合は、文字の境目で切り詰める必要がある。
- 下書きの間は slug の重複を確認しない。公開時に重複していれば WordPress が `-2` を付ける。
- **この版の TruSEO には URL のキーワードを判定する項目が無い。** 日本語 slug にしても英語 slug にしても点数は変わらない。
- 日本語 slug は AIOSEO の点数を上げる目的で選んだ方針だったため、再確認のうえ **slug は現状の `article-番号` を維持する** と決定した（2026-09-14）。WBS の 2.5 は削除した。
